# TNF Open Runtime Frontload Workflow

Use the manifest-derived public agent rail. Do not maintain a second hard-coded ontology in a host prompt.

1. Run `pnpm run tnf:onboard -- --task "<task>"`.
2. Confirm the open-agent rail gate passes and reports hashes for the required public rails.
3. Orient repository/runtime state.
4. Before mutation, classify work/destination/residency/sensitivity and use `--write-ready`.
5. Hydrate only task-relevant source.
6. Discover/staff capabilities under current authority and boundary constraints.
7. Act with bounded scope.
8. Verify empirically.
9. Generalize reusable learning without copying private context.
10. Leave a receipt/handoff when continuation requires it.

If a private hosted TNF capability is unavailable, continue under a valid local/operator policy where possible. Do not interpret missing proprietary optimization as permission to bypass public TNF gates or as loss of all local agency.
